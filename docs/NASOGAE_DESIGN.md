# 나 소개·성격(selfIntro) 설계 문서

이 문서는 밤샘 작업 지시의 1단계 산출물이다. 코드는 아직 쓰지 않았다 — 2단계에서 이 설계를 그대로 구현한다. 0단계 조사(같은 대화의 이전 보고 참고) 결과를 전제로 삼는다.

## 0. 핵심 결정 (오너 확정 — 바꾸지 않음)

- 태그는 이상형과 **완전히 동일한 4축 18개**를 쓴다. 축 키(axisId): `relationship`, `lifestyle`, `experienceStressResponse`, `binary1`.
- 차이는 방향뿐이다 — 이상형은 "내가 원하는 상대", 나소개는 "나는 이렇다".
- `engine/ideal-type-tags.ts`의 `TAG_CATEGORIES`는 **`label` 문자열을 키로 매핑**한다(axisId가 아니라). 즉 나소개 쪽 4개 축의 **선택지 label 텍스트가 이상형 쪽과 1글자도 다르지 않게 동일**해야 `getIdealTypeTags()`가 그대로 재사용된다. `description`(부연 설명)은 자유롭게 다시 쓸 수 있다 — 태그 매핑은 `label`만 본다.

## 1. 태그 18개 자기서술 검증

이상형 쪽 4개 축의 실제 옵션 label(코드에서 그대로 가져옴)을 "나는 ___이다"로 읽어봤다.

### relationship축(연애할 때 원하는 것 → 나소개: 연애할 때 내가 실제로 해주는 것)
| label | 태그 | 자기서술로 읽었을 때 |
|---|---|---|
| 표현 많이 해주기 | #표현중시형 | 어색함 있음 — "해주기"가 원래 "상대가 나한테 해주는 것"을 뜻하는 수혜격 어미라, 그대로 읽으면 "내가 표현을 받는 걸 좋아한다"로 오해될 수 있다. 질문을 "내가 상대에게 실제로 잘 해주는 것은?"으로 뒤집으면 "내가 표현을 많이 하는 편"으로 자연스럽게 성립한다. |
| 서로 존중하는 거리감 | #거리존중형 | 자연스러움 |
| 함께 많은 시간 | #함께시간형 | 자연스러움 |
| 티키타카 잘 통하기 | #티키타카중시형 | **★어색함 — 지적만 하고 바꾸지 않음.** "티키타카"는 정의상 양방향 케미인데, 이걸 "나는 티키타카중시형이다"로 혼자 자기서술하면 상대 없이는 성립 안 되는 특성을 혼자 가진 것처럼 말하게 된다. 다른 17개와 달리 이것만 "내가 하는 행동"이 아니라 "관계의 속성"이라 방향 전환이 매끄럽지 않다. 오너 판단 필요. |
| 든든한 안정감 | #안정감중시형 | "내가 상대에게 주는 것" 프레임으로 자연스러움 |
| 빠른 갈등 해결 | #갈등해결형 | 자연스러움(오히려 원래도 행동 묘사에 가까움) |

### lifestyle축(잘 맞는 생활 → 나소개: 내 실제 생활)
| label | 태그 | 자기서술 |
|---|---|---|
| 집순이·집돌이 / 액티브·야외파 / 취미 공유 / 각자 시간 존중 / 여행 좋아하는 / 규칙적인 생활 | 6개 전부 | **전부 자연스러움.** 이 축은 이상형 쪽에서도 이미 "이런 사람"이라는 인물 유형 표현이라, 방향을 뒤집을 필요 자체가 없다. |

### experienceStressResponse축(갈등 대처 → 나소개: 동일)
| label | 태그 | 자기서술 |
|---|---|---|
| 바로 이야기하는 편 / 혼자 삭이는 편 / 거리를 두는 편 / 주변에 털어놓는 편 | 4개 전부 | **전부 자연스러움 — 이 축은 이상형에서도 이미 `aboutSelf: true`로 본인 얘기를 묻고 있어서 질문·옵션을 그대로 재사용 가능.** |

### binary1축(관계 리듬 → 나소개: 동일)
| label | 태그 | 자기서술 |
|---|---|---|
| 오래 편안한 사람 / 매일 설레는 사람 | 2개 전부 | **자연스러움** — "~한 사람"이라는 인물형 표현이라 원래도 자기서술에 가깝다. |

**결론**: 18개 중 확실히 어색한 건 **`#티키타카중시형` 1개뿐**이다. `relationship`축의 나머지 5개는 질문 프레임을 "내가 상대에게 해주는 것"으로 두면 해결된다. 나머지 두 축(lifestyle, binary1)은 원래도 인물형 표현이라 손댈 게 없다. `#티키타카중시형`은 표시만 하고 그대로 둔다 — 오너 판단 대기.

## 2. 문항 설계

### 2.1 원칙
- **자기평가 문항 금지.** "나는 계획적인 편이다" 같은 추상 형용사 자기서술은 만들지 않는다.
- 전부 **"실제로 있었던 일 → 그때 실제로 한 행동"** 형태로 묻는다. `topics.ts`의 `experience`/`scenario` 타입이 이미 이 형태다 — 이상형의 experienceStressResponse가 정확히 이 패턴("가까운 사람과 갈등이 있을 때, 스트레스를 어떻게 푸는 편이야?")이므로, 나소개의 새 축들도 전부 이 화법을 따른다.
- 4개 태그 축 중 `binary1`은 이진 선택("오래 편안한 사람 vs 매일 설레는 사람")이라 형식상 완전한 "경험 서술"은 아니다. **이 축만은 이상형에서도 원래 binary 타입(선호 강제택일)이라, 나소개에서도 같은 형식을 유지한다** — 다만 질문을 "실제 연애/관계에서 시간이 지날수록 어느 쪽에 더 가까워졌어?"처럼 과거 경험에 걸쳐서 묻는 것으로 최대한 행동 근접하게 만든다. 완전한 자기평가는 아니지만 형용사 나열도 아닌 절충점이다 — 이 지점은 오너 검토를 권한다.

### 2.2 축 구성 (필수 34 + 심화 6 = 40, 이상형과 동일 규모)

**A. 태그 결정 축 4개 (이상형과 label 완전 동일, 필수)**

| id | type | 질문 프레임(초안) |
|---|---|---|
| `relationship` | preference | "가까운 사람과의 관계에서, 나는 실제로 무엇을 더 자주 해주는 편이야?" (label 6개 이상형과 동일 문자열 그대로) |
| `lifestyle` | preference | "실제 생활에서, 나와 더 가까운 모습은?" (label 6개 동일) |
| `experienceStressResponse` | experience | 이상형과 완전히 동일한 질문·옵션 재사용(이미 본인 얘기라 그대로 씀) |
| `binary1` | binary | "연애/가까운 관계가 오래될수록, 실제로 나는 어느 쪽에 더 가까웠어?" (label 2개 동일) |

**B. 그 외 축 36개 — "사람 전반"을 다루는 새 문항. 이상형의 축 카테고리를 참고해 대응시켰다.**

| 영역 | 개수(대략) | 예시 질문 방향 | 형식 |
|---|---|---|---|
| 일할 때 실제 모습 | 4 | "마감이 촉박했던 실제 프로젝트에서, 그때 나는 어떻게 움직였어?" | experience/scenario |
| 갈등·의견 차이(비연애, 친구·동료) | 4 | "친구와 의견이 갈렸던 실제 상황에서, 그때 나는 뭐라고 했어?" | scenario |
| 결정 방식(실제 사례) | 3 | "최근 뭔가를 정할 때, 실제로 어떤 순서로 정했어?" | quickTap |
| 감정 표현 방식(실제 경험) | 3 | "정말 기뻤던 순간, 그걸 실제로 어떻게 표현했어?" | experience |
| 관계에서 맡는 역할(실제 사례) | 3 | "모임에서 누군가 힘들어했을 때, 실제로 나는 어떻게 했어?" | scenario |
| 실패·후회 경험 | 3 | "돌아보면 아쉬웠던 선택, 그때 실제로 어떻게 했어?" | experience + reflection 1개 짝 |
| 쉴 때 실제 모습 | 3 | "정말 피곤했던 날, 실제로 뭘 하며 쉬었어?" | quickTap |
| 소통 방식(실제 사례) | 3 | "오해가 생겼던 실제 대화에서, 그 다음에 나는 뭘 했어?" | experience |
| 성장 계기(실제 경험) | 3 | "스스로 달라졌다고 느낀 실제 계기가 있었다면?" | reflection |
| 사람 대하는 태도(실제 사례) | 3 | "처음 보는 사람과 있었던 실제 상황에서, 나는 어떻게 행동했어?" | scenario |
| 심화(선택, 6개) | 6 | 위 영역의 더 구체적인 후속 질문(예: 성장 계기의 "그 이후 뭐가 달라졌어?") | reflection/experience |

이 표는 축의 **개수와 형식·화법**을 확정한 것이고, 각 축의 실제 옵션 6~4개(label+description+subOptions) 전문(全文)은 2단계 구현 시 `topics.ts`에 직접 작성한다 — 이상형의 실제 문항 텍스트 수준(예: `experienceApology`, `scenarioCancel` 등)과 동일한 밀도로 쓸 예정이다. 여기서 전부 미리 쓰지 않는 이유는, 설계 문서 단계에서 40개 문항의 세부 문구까지 확정하면 구현 중 실제 흐름을 타보며 다듬을 여지가 없어지기 때문이다 — 축 구조와 화법 원칙, 태그 매핑 4축만 이 단계에서 고정한다.

**목표 소요 시간 7~8분 — 줄이지 않는다.** 이상형(필수 34+심화6)과 문항 수·형식 비율을 동일하게 맞췄으므로 소요 시간도 비슷할 것으로 예상한다(실측은 2단계 Playwright 완주 시간으로 확인).

### 2.3 각 문항이 결정하는 축 표기
`topics.ts`의 각 axis 객체에 그대로 대응한다 — A그룹 4개는 태그 축 이름 자체가 곧 그 축이고, B그룹 36개는 태그 시스템과 무관하게 `attractionPatterns`(나소개에서는 아래 4번 참고, 반복 패턴)의 재료로만 쓰인다. 즉 **태그를 결정하는 축은 정확히 4개뿐**이고 나머지 36개는 AI가 패턴을 짚어내는 원료다 — 이상형도 정확히 같은 구조다(태그 축 4개 + 나머지 30개는 결과 텍스트 재료).

## 3. "연애 스타일" 주제와의 경계

- **문제**: `relationship`·`binary1` 두 태그 축은 원래 이상형에서 "연애"를 전제로 설계된 문항이라, 나소개에서도 이 두 축만큼은 연애 맥락을 완전히 벗어나기 어렵다. **★완전 분리는 불가능하다는 점을 인정한다.**
- **경계 제안**: 태그 4축 중 2개(`relationship`, `binary1`)만 "가까운 관계"(연애로 한정하지 않고 "가까운 사람"으로 열어둠 — 위 질문 프레임에 이미 반영)로 최소한만 걸치고, 나머지 34개 문항(B그룹)은 일·친구·의사결정·감정·휴식 등 **연애와 무관한 영역으로 채운다.** 이렇게 하면 40문항 중 연애가 명시적으로 등장하는 건 많아야 2~4문항(태그 축 관련)뿐이고, 나머지는 "연애 스타일"(`loveStyle`, "내가 연애에서 반복하는 패턴")과 소재가 겹치지 않는다.
- **`loveStyle`과의 실질적 차이**: `loveStyle`은 연애 안에서의 반복 패턴만 파고드는 주제로 남겨두고, `selfIntro`는 "일·관계·결정·감정·휴식 전반"을 다루되 태그 계산용으로만 연애 문항 2~4개를 빌려 쓰는 구조로 제안한다. 두 주제가 나중에 둘 다 만들어지면, `loveStyle` 결과 화면엔 "나소개도 해보세요" CTA를, `selfIntro` 결과 화면엔 "연애만 더 깊게 보고 싶다면 연애 스타일도 있어요" CTA를 서로 안내하는 정도로 역할을 나눌 수 있다(이건 2단계 스코프는 아니고 향후 옵션으로만 제안).
- **이름 충돌 주의(0단계에서 이미 보고)**: "궁합"이라는 단어가 이미 두 곳에 있다(`topics.ts`의 `compatibility` 주제, `#107`의 코드 비교 기능). 이번에 나소개×이상형 교차 비교를 만들면 **세 번째 "궁합" 개념**이 생기는 셈이다. 화면 문구에서 "궁합"이라는 단어를 쓸지, 다른 표현("교차 매치" 등)을 쓸지는 오너 판단이 필요하다 — 여기서는 문제 제기만 하고 임의로 이름을 짓지 않는다.

## 4. 결과 블록 구성

이상형의 6블록(기준·패턴·매트릭스·신호등·자기성찰·로드맵) 대응안:

| 이상형 블록 | 나소개 대응 블록 | 반전 구조 유지 방법 |
|---|---|---|
| criteria(기준) | **핵심 가치 3단계**(꼭 지키는 것 / 중요하게 여기는 것 / 유연하게 넘어가는 것) — 답변에서 추론 | AI가 답변 패턴에서 역으로 추론해서 제시 — 사용자는 "나는 이런 가치관이다"라고 직접 말한 적 없다 |
| attractionPatterns(끌림 패턴) | **반복되는 행동 패턴**(여러 경험형 답변을 교차해서 짚는 통찰) | 그대로 유지 — 이상형과 동일한 원리(여러 답변을 가로질러야만 나오는 통찰) |
| matrix(2x2 매트릭스) | **성향 매트릭스**(예: 신중함↔즉흥성 × 표현함↔절제함, 답변 좌표를 AI가 배치) | 그대로 유지 |
| flags(신호등) | **강점/주의점**(green: 이 사람과 잘 지내려면 알아두면 좋은 점 / red: 부딪힐 수 있는 지점) — "타인이 나를 볼 때"의 시점 | 사용자가 준 재료(행동 답변)로 AI가 "타인 시점"을 만들어내는 게 반전 포인트 |
| selfReflection(자기성찰: 내가 줄 수 있는 것/개선할 점) | **그대로 유지** — 이상형과 동일한 발상(여러 답변 교차) | 그대로 |
| roadmap(로드맵) | **"이런 상황에서 시도해볼 것"**(관계·일에서 다음에 해볼 만한 작은 행동 제안) | 그대로 |

**반전 구조 핵심**: 이상형은 "상대 이야기인 줄 알았는데 마지막에 내 얘기가 나온다"가 반전이었다. 나소개는 처음부터 "내 얘기"라고 밝히고 시작하므로 **그 반전은 원천적으로 없다.** 대신 반전을 이렇게 옮긴다 — "행동만 물었는데, 마지막에 '이런 사람'이라는 요약이 나온다"는 반전이다. 사용자는 시종일관 "이럴 때 실제로 뭐 했어?"라는 행동 질문에만 답하고, "당신은 이런 사람입니다"라는 인물 묘사는 사용자가 한 번도 직접 말하지 않았는데 AI가 종합해서 던져준다 — 질문(행동)과 결과(인물 묘사) 사이의 간극이 반전이다. 이건 이상형의 원리(주어진 재료로 스스로 몰랐던 패턴을 짚어줌)와 본질적으로 같은 장치를 다른 곳에 적용한 것이다.

### "나에 대해" 라벨(#119) 처리
**나소개에는 이 라벨을 붙이지 않는다(전 문항 `aboutSelf` 미설정, 기본값 `undefined`로 둠).** 이 라벨은 원래 "이상형 얘기인 줄 알았는데 갑자기 내 얘기를 묻는 전환"을 표시하려고 만든 것인데, 나소개는 처음부터 "나에 대해 묻는다"고 밝히고 시작하는 주제라 전환 자체가 없다 — 40문항 내내 라벨을 붙이면 오히려 매 화면에 뜨는 불필요한 반복 요소가 된다. 코드로는 `aboutSelf` 필드를 selfIntro의 어떤 axis에도 `true`로 설정하지 않는 것으로 처리(구현은 자연히 "안 함"이 되므로 추가 분기 코드 불필요).

## 5. 메시지 개수 상한

이상형과 완전히 같은 계산 방식을 그대로 재사용한다. `app/api/generate-idealtype-result/route.ts`의 `maxIdealTypeMessages()`를 그대로 본떠, 나소개 전용 라우트에 아래 함수를 만든다:

```ts
function maxSelfIntroMessages(): number {
  const axisCount = (resolveTopic("selfIntro").axes ?? []).length; // 40
  return axisCount * 2 * 2 + 10; // 40 * 4 + 10 = 170 (이상형과 축 수가 같으면 상한도 같다)
}
```

축 수가 이상형과 동일(40)하게 설계했으므로 상한값도 동일하게 170이 된다. 이후 나소개 문항 수가 바뀌어도 이 함수가 자동으로 따라가므로 #81류 사고(상한 하드코딩 → 문항 수 변경 시 정상 사용자가 결과를 못 받는 사고)가 재발하지 않는다 — 이상형에서 이미 검증된 패턴을 그대로 복제하는 것이라 새로 설계할 게 없다.
